# AlphaLens 当前能力、待建设能力与未来路线图

## 1. 当前产品阶段

AlphaLens 当前定位为：

> 比赛可完整演示、核心后端可运行、具备数据治理和质量门禁的受控 Beta。

P0 工程能力、P1 个人研究工作台和 P2 组合辅助决策已落地；正式商用仍取决于数据许可、消息通道认证、法律审查、全局限流、删除作业 SLA 与高可用演练。

## 3. 现在还不能做什么

以下能力尚未完成，不应在比赛或产品介绍中误称为已具备：

- 未授权情况下的实时/延时行情和一致预期；
- 依赖 JavaScript 且没有官方 Feed 的复杂 IR 网站；
- 财报电话会商业版权内容和实时新闻；
- 外部 LLM 的正式调用（字段与追踪表已就绪）；
- 全量行业口径标准化和自动修复式 Tie-out；
- 券商账户自动同步和经授权的标准化因子数据；
- 自动化回测；
- 券商连接或自动交易；
- 正式金融数据商业授权；
- 面向正式商业运营的法律与合规审查。
- 未配置 Resend、企业微信官方 Webhook 或微信公众号授权时的真实消息发送；
- 催化剂订阅的托管 Cron（内部 Worker 已实现，部署环境仍需配置周期调用）；
- 自动填充同行财务指标（当前保存用户或授权 Provider 提供的有来源快照，不使用未授权聚合数据）。

## 6. 未来可以做什么

### 6.1 个性化研究记忆

系统可以学习用户的研究范围、指标偏好和历史错误，但只用于改进研究流程。例如识别用户是否经常：

- 忽略估值；
- 过度相信管理层指引；
- 在财报前承担过大事件风险；
- 把短期价格变化当成基本面变化；
- 在论点失效后继续修改故事。

个性化不能变成不透明的自动荐股模型。

### 6.2 自动论点监控

每条论点关联一组证据、KPI 和事件。当新财报、公告或行业数据出现时，系统只重新评估受影响的节点，并解释：

- 哪条证据发生变化；
- 为什么论点增强或弱化；
- 哪个情景概率需要调整；
- 是否触发证伪条件。

### 6.3 市场隐含预期引擎

将估值模型反向求解，回答当前价格隐含：

- 多高的收入增长；
- 多高的利润率；
- 多长的竞争优势持续期；
- 多低的资本成本；
- 多高的事件成功概率。

这会成为 AlphaLens 相比普通 AI 公司总结工具的重要差异化能力。

### 6.4 研究复盘与方法改进

系统可以在季度或年度层面分析：

- 哪类论点判断更准确；
- 主要错误来自数据、模型、逻辑还是时点；
- 哪些来源经常产生错误信号；
- 哪些证伪条件设得过松或过严；
- 用户在哪些行业具备或缺乏研究优势。

目标是提高决策过程质量，而不是只统计交易盈亏。

### 6.5 WorkBuddy 多入口协作

未来可利用 WorkBuddy 的任务、Skill、连接器和 IM 入口实现：

- 在桌面端发起深度研究；
- 在移动端查看催化剂提醒；
- 将研究结果写入腾讯文档；
- 从企业微信或微信提交复核任务；
- 在团队环境中完成研究、反方审查和审批。

## 7. 建议里程碑

| 阶段 | 建议周期 | 交付目标 | 退出标准 |
|---|---:|---|---|
| Competition Demo | 已完成 | 完整演示研究闭环 | 现场流程稳定、核心交互可用 |
| Private Alpha | 2–4 周 | SEC + 行情 + 持久化 | 一只股票能真实完成研究与更新 |
| Closed Beta | 已完成核心工程 | 用户系统 + 观察池 + 催化剂 | 多用户隔离、数据可追踪 |
| Research Beta | 已完成 P1 核心工程 | 财报工作流 + 复盘 + 质量体系 | 生产数据/消息凭据配置后进入用户验证 |
| Portfolio Beta | 12 周以上 | 组合风险和行动条件 | 组合层风险解释稳定且可审计 |

周期是对小型工程团队的粗略估计，取决于数据授权、Provider 质量和合规要求。

## 8. 非目标

AlphaLens 暂不追求：

- 高频交易；
- 短线涨跌预测；
- 无法解释的综合荐股分；
- 自动执行证券交易；
- 同时覆盖所有资产类别和全部市场；
- 以生成更多资讯替代真正的研究判断。

## 9. 成功指标

产品成熟后建议衡量：

- 权威来源覆盖率；
- 关键结论引用率；
- 财务数字核对准确率；
- 证伪条件覆盖率；
- 研究任务完成时间；
- 新事件后的论点更新时间；
- 数据陈旧性和 Provider 失败率；
- 人工抽检通过率；
- 用户复盘完成率；
- 相比手工研究节省的时间。

不建议把短期收益率作为唯一产品指标，因为这会鼓励系统输出过度自信、不可解释的方向性结论。
